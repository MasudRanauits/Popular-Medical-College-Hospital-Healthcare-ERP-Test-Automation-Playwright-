2. Scope and environment

In scope Authentication, module launcher, Patient Registration list and create-patient wizard, New Admission wizard (Patient / Contact Person / Advance Payment / Admission Detail), the admission dashboard — looking an admission up and printing its paperwork — host availability, and one end-to-end register-then-admit flow.
Out of scope OPD, Pharmacy, Diagnostic, HR, Accounts and Billing modules; the ID-card print and the admission dashboard's list-level Print List / Print Package List buttons; what is inside a printed document, which is checked as a valid, non-empty PDF and no further; role-based permissions beyond the Administrator account; performance and security testing.
Environment ERP web application over HTTPS on the hospital host (BASE_URL in .env; self-signed certificate, so ignoreHTTPSErrors is on). Live database — see the warning in section 5.
Browser Chromium (Desktop Chrome profile) at 1920×1080, headed, one worker. Firefox and WebKit projects exist in playwright.config.ts but are commented out; mobile viewports are not enabled.
Test account Administrator account read from ERP_USERNAME / ERP_PASSWORD. Credentials never appear in source control or in this document.
Session handling tests/auth.setup.ts logs in once and saves the browser state to playwright/.auth/user.json. Signed-in suites reuse it; signed-out suites clear it with test.use({ storageState: { cookies: [], origins: [] } }).
Timeouts 90 s per test, 15 s per assertion, 30 s per action, 45 s per navigation — raised from the Playwright defaults because the host is slow. Three cases raise their own further (noted in their rows).

5. Data safety

Two cases write to the live hospital database and nothing in the suite undoes them: TC_SMK_ADM_004 stops short of the submit but fills the wizard, and TC_FLOW_001 registers a patient and admits them, which holds a real bed and records real advance payments. Cancelling an admission is its own workflow under Hospital > Admission Cancel. Run TC_FLOW_001 deliberately, and expect a Masud Rana Test-<n> patient after each run. Every other case is read-only: the registration and admission cases deliberately stop before any Confirm button, and the admission dashboard cases only search and print — a printed document changes nothing in the record it is printed from.

How a printed document is checked. The app does not navigate to a document or download one — it builds the file in the browser and opens a tab on a blob: URL, which renders in the browser's own PDF viewer and has no readable page behind it. The blob belongs to the dashboard, which created it, so the test fetches that URL from the dashboard and gets the actual bytes. That is what makes "the button printed something" checkable rather than just "a tab opened" — a page that failed to render would open a tab too.

Not clicked: some rows carry a cloud-arrow-down button among the print buttons. It produced nothing observable on any row tried — no tab, no download, nothing on screen — so the print run matches on the printer icon and steps over it rather than hanging on a document that never comes. Worth a question to the module owners; it is not raised as a defect because what it is meant to do is unknown.

Grid search and row actions on the patient list (the old TC_REG_005–007) Removed from the spec; the cases keyed off live data that was not stable enough to assert on. Re-add against a patient the test registers itself, the way TC_FLOW_001 does.
